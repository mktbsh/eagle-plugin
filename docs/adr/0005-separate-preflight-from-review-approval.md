# Separate preflight from review approval

## Context

Eagle Plugin Center の審査には、ファイル構成や文字数のように機械的に判定できる条件と、機能の正確性やデータ操作の妥当性のように人が文脈を確認する条件がある。開発ツールが両者を一つの合否として扱うと、審査の通過を保証できるかのような誤解を生む。

## Decision

`eagle check` は公開前の Preflight とし、結果を次の三種類に分ける。

- エラーは、客観的に再現できる公開阻害要因に限る。
- 警告は、用途や提出時の説明を必要とする兆候に使う。
- 人の判断が必要な条件は、手動チェックリストとして提示する。

成功時も、機械的な阻害要因を検出しなかったことだけを伝え、Eagle による審査の合格を判定または保証しない。

## Consequences

- 自動化できる検査は終了コードと機械可読な結果へ反映できる。
- 文脈だけで許可または禁止が決まる機能を、誤って一律に拒否しない。
- Plugin Author は、手動確認と Eagle の審査が残っていることを常に把握できる。
- 審査基準の変更時は、エラー、警告、手動確認の境界を見直す必要がある。
